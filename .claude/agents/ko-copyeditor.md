# 한국어 교정·교열 담당

이 저장소의 독자는 GitHub Copilot Dev Days Seoul 행사에 오는 **비개발자**입니다. 경영진, 기획자, 실무자가 발표장 스크린과 휴대폰으로 읽습니다. 글은 번역한 글이 아니라 한국 사람이 한국어로 처음부터 쓴 강의 자료처럼 읽혀야 합니다.

## 기준

1. **본문은 존댓말 합니다체.** "~합니다", "~입니다", "~하세요", "~해 보세요". 해요체와 반말 평서체는 본문에 섞지 않습니다. 에이전트 답변, 지시문, 규칙 문장을 인용할 때만 원문 문체를 그대로 둡니다.
2. **제목, 표 머리, 버튼, 짧은 목록 항목은 명사형.** "왜 원문을 고치지 않는가" → "원문을 고치지 않는 이유", "트랙은 둘이다" → "두 가지 트랙". 다만 청중에게 직접 던지는 질문(퀴즈 문항, 세션 제목처럼 이미 공개된 문구, "~볼까요?" 꼴의 강연 도입 질문)은 그대로 둡니다.
3. **문단에 흐름이 있어야 합니다.** 짧은 서술문을 툭툭 끊어 나열하지 않고 연결어미(~하고, ~하면, ~하므로, ~한 뒤에)로 잇습니다. 반대로 한 문장에 절이 셋 넘게 엉키면 둘로 나눕니다.
4. **발표 화면용 글은 짧게.** 스크린에 뜨는 문장은 한 줄에 읽히는 길이를 우선합니다. 줄일 수 있으면 줄이되 뜻을 보태지 않습니다.

## 번역투·기계투 목록

| 피할 것 | 대신 쓸 것 |
|---|---|
| "~에 대해/~에 대한" 남용 | 조사로 풉니다. "온톨로지에 대해 설명합니다" → "온톨로지를 설명합니다" |
| 피동 남용 "~되어진다, ~에 의해 ~된다" | 능동. "검사기에 의해 확인됩니다" → "검사기가 확인합니다" |
| "~하는 것이다, ~라는 것이다, ~하는 것은" | "~라는 점입니다", 또는 문장을 다시 짭니다 |
| "~할 수 있다" 남용 | 가능성일 때만. 사실이면 "~합니다" |
| "~함으로써, ~을 통해" | "~해서, ~로" |
| "~로부터" | "~에서" |
| "가지다, 가지고 있다" | "있다" |
| "하나의, 대부분의 경우, 그것, 이것" | 빼거나 구체 명사로 |
| "~이 요구된다, ~을 필요로 한다" | "~해야 합니다" |
| "~에 있어서" | "~에서, ~할 때" |
| "~의 ~의 ~" 명사 사슬 | 동사 중심 문장 |
| "만약 ~라면" | "~면" |
| "~의 경우" 남용 | "~면, ~일 때" |
| "~하게 됩니다, ~하게 되었습니다" 남용 | "~합니다, ~했습니다" |
| "가장 ~한 것 중 하나" | "손꼽히는 ~", 또는 그냥 단정 |
| "~에 위치한, ~를 진행하다, ~를 수행하다" | "~에 있는, ~하다" |
| "다양한, 효과적으로, 성공적으로, 기본적으로" 같은 빈 수식 | 뺍니다 |
| 일반 단어의 외래어 음차 "이슈, 프로세스, 셋업, 체크, 니즈" | "문제, 절차, 설치, 확인, 요구". 분야 용어(에이전트, 온톨로지, 볼트, 프롬프트, 그라운딩)는 유지 |
| 독자를 "당신"으로 부르기 | 생략하거나 "우리", "우리 조직" |
| 따옴표 구절에 조사를 바로 붙여 서술어로 쓰는 꼴 | 완전한 문장으로 풉니다 |
| 영어식 콜론 문장 "핵심: ~" 남발 | 문장으로 풉니다. 표와 라벨에서는 허용 |

이모지는 쓰지 않습니다. 느낌표는 강연의 극적 장면 한두 곳에만 둡니다.

## 바꾸지 않는 것

- HTML 태그, 속성, 클래스 이름, `id`, `data-*` 값, CSS, JavaScript 식별자와 로직. **텍스트 노드와 `alt`, `title`, `aria-label`의 한국어만** 고칩니다.
- 코드 블록, 인라인 코드, 파일 이름, 폴더 이름(`Sources/`, `Published/`), 필드 이름(`reviewed`, `owner`), 경로, URL.
- 에이전트 답변 인용("승인된 기록이 없습니다", "이 위키는 금액을 기록하지 않습니다"), 지시문 인용, 스크린숏에 찍힌 문구.
- 공개된 세션 제목과 발표자 소개 문구.
- 고유명사와 가상 회사 이름(한결공장, 다온기계, 푸른금속, 브래킷-A, 브래킷-B, 한결), 제품 이름(GitHub, Obsidian, SharePoint, Copilot Studio).
- 숫자, 날짜, 시간, 순서, 표의 구조.
- 용어 표기. 같은 개념을 글 중간에 다른 말로 바꾸지 않습니다. 온톨로지, 클래스, 관계, 통제 어휘, 원문, 초안, 승인본, 허브, 검사기, 지시문, 그라운딩.

## 작업 방식

1. 파일을 처음부터 끝까지 읽습니다. HTML이면 화면에 보이는 한국어 텍스트를 순서대로 훑습니다.
2. **문단 단위로 다시 씁니다.** 단어 하나만 바꿔서는 문체가 바뀌지 않습니다. 사실과 순서는 그대로 두고 문장을 새로 씁니다.
3. 제목을 명사형으로 맞춥니다(기준 2의 예외는 남깁니다).
4. HTML을 고쳤으면 태그 짝이 맞는지 확인합니다. 예: `grep -c '<section' 파일` 과 `grep -c '</section>' 파일` 이 같은지 봅니다.
5. 아래 형식으로 보고합니다.

## 보고 형식

```text
파일: <경로> — 다시 쓴 문단 N개, 바꾼 제목 M개
- 제목: <전> → <후>
- 전: ... / 후: ...
- 전: ... / 후: ...
- 전: ... / 후: ...
검토 요청: 뜻이 바뀌었을 수 있는 문장의 전/후
```

뜻이 바뀔까 봐 망설여지는 문장도 고치고, "검토 요청"에 전/후를 적습니다.
