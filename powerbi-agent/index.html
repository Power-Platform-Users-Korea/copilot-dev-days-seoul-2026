과거 방식 (Without Authoring Skills)

단순 프롬프트 + 기본 MCP만 사용했을 때

  • 기능 한계: DAX 측정값 생성과 1페이지짜리 기본 차트 4~5개 배치에만 그침
  • 디자인 부재: 한글 폰트(맑은 고딕/Pretendard) 최적화, 여백, 색상 조화, 시각적 계층 구조가 없는 투박한 결과물
  • 검증 불가 (맹목적 생성): 에이전트가 JSON 파일만 뱉어낼 뿐, 실제 화면에서 한글 레이블이 잘렸는지 차트가 깨졌는지 스스로 확인하지 못함
신규 방식 (June 2026 MS Authoring Skills)

공식 Agent Skills + 2종 CLI + Desktop Bridge 결합

  • End-to-End 워크플로우: 요구사항 기획(Planner) → 디자인 아키타입(Design) → PBIR 코드 생성(Authoring) → 배포(Management)
  • 자체 시각 검수 루프 (Self-Correction): 에이전트가 직접 Power BI Desktop을 새로고침(Reload)하고 스크린샷을 찍어 눈으로 보고 깨진 UI를 스스로 고침
  • 기업 표준 일관성: 한국형 브랜드 테마(Retail_IQ_Light_KR.json)와 모던 비주얼/네비게이션 바를 완벽 적용

Chapter 01 · Tech Stack 현재 위치: 시스템 설계소

전체 워크플로우를 지탱하는 5계층 기술 스택

에이전트가 한글 데이터를 이해하고(Semantic Model), 화면을 그리고(PBIR Report), 눈으로 확인(Desktop Bridge)하기 위해 필요한 전체 구성 요소입니다.

계층 (Layer) 핵심 구성 요소 역할 및 기술적 상세 설명
1. 프로젝트 파일 계층 PBIP / PBIR / TMDL • PBIP (Power BI Project): 단일 바이너리(.pbix)는 외부 AI가 수정할 수 없으므로 반드시 폴더 기반 프로젝트 포맷인 K_Retail_Sales_Demo.pbip로 변환해야 합니다.
• TMDL: 시맨틱 모델(테이블, 한글 컬럼, 1:N 관계, DAX 측정값)을 정의하는 텍스트 언어입니다.
• PBIR: 리포트 페이지, 비주얼 좌표/바인딩, 필터, 테마(report.json)를 담는 JSON 포맷입니다.
2. 에이전트 런타임 Claude Code / Copilot CLI • 로컬 파일 시스템을 읽고 쓰며, 터미널 명령어(CLI)와 MCP 도구를 호출하는 멀티모달 LLM 호스트입니다.
• 영상에서는 Claude Code에서 Bypass Permissions 모드를 켜서 사람의 개입 없이 루프를 돌렸으며, VS Code 기반 GitHub Copilot에서도 동일하게 동작합니다.
3. 시맨틱 모델 제어 Power BI Authoring MCP • 구 명칭: Power BI Modeling MCP Server.
• 실행 중인 Power BI Desktop의 로컬 Analysis Services(XMLA) 인스턴스에 연결하여 스키마를 프로파일링하고, 라이브 DAX 쿼리를 실행하며, 한글 KPI 측정값을 생성/검증합니다.
4. 리포트 생성 & 브릿지 powerbi-report-author
powerbi-desktop		 • Report Authoring CLI: PBIR JSON 스키마 생성, 최신 비주얼 메타데이터 조회 및 구문 검증(validate)을 수행합니다.
• Desktop Bridge CLI: 실행 중인 Power BI Desktop 화면을 즉시 새로고침(reload)하고 페이지별 PNG 스크린샷(screenshot)을 캡처합니다.
5. 지능형 작업 지침서 microsoft/skills-for-fabric • Microsoft가 공식 배포하는 에이전트 플러그인 모음(powerbi-authoring)입니다.
• 기획(planning), 디자인(design), 구현(authoring), 배포(management) 4대 스킬이 에이전트의 행동 규칙(MUST/PREFER/AVOID)을 통제합니다.

Chapter 02 · K-Retail Dataset & PBIP 현재 위치: 프로젝트 폴더 보관소

실습 데이터셋(K-Retail)과 .pbip 폴더 해부도

실습 패키지(K_Retail_PowerBI_Agent_실습패키지.zip)에 포함된 5개의 한글 CSV 파일을 Power BI Desktop에 로드한 뒤, 파일 > 다른 이름으로 저장 > Power BI project files (*.pbip)로 저장하면 아래 우측과 같은 코드 구조가 생성됩니다.

한결전자 데이터 모델 (Star Schema · 5종 CSV)

1개의 Fact 테이블 + 4개의 Dimension 테이블

  • Fact_Sales.csv (매출 팩트 · 2,356건): 주문번호, 주문항목번호, 주문일자, 배송완료일자, CustomerKey, StoreKey, ProductKey, 주문수량, 통화코드(KRW)
    ★ 핵심 설계 포인트: 주문수량만 있고 단가 컬럼이 없습니다! 에이전트가 MCP를 통해 스스로 Dim_Products를 스캔하여 단가를 찾아내도록 설계되었습니다.
  • Dim_Products.csv (제품 차원 · 18종): 갤럭시 북4 프로, 그램 프로, 올레드 에보 TV, 비스포크 AI 콤보 등 한글 제품명, 카테고리, 브랜드(삼성/LG/쿠쿠), 원가_KRW, 판매단가_KRW
  • Dim_Stores.csv (매장 차원 · 12곳): 강남 본점, 여의도 더현대점, 판교 테크노밸리점, 공식 온라인몰 등 매장명, 권역(서울/수도권/영남권/온라인 등), 매장유형, 매장면적_제곱미터
  • Dim_Customers.csv (고객 차원 · 200명): 고객명, 성별, 연령대, 거주권역, 고객등급(VIP/골드/실버/일반)
  • Dim_Date.csv (날짜 차원 · 2024~2026): Date, 연도, 분기, 월, 연월, 평일주말구분
디스크 폴더 해부도 (Anatomy of PBIP)

K_Retail_Sales_Demo.pbip 저장 시 생성 구조

K_Retail_Practice/
├── Fact_Sales.csv 외 4개 CSV          # 원본 한글 실습 데이터
├── Retail_IQ_Light_KR.json            # 한국형 커스텀 테마 JSON
├── K_Retail_Sales_Demo.pbip           # 프로젝트 진입점 파일
├── K_Retail_Sales_Demo.SemanticModel/ # [MCP 담당 영역]
│   └── definition/
│       ├── tables/                    # Fact_Sales.tmdl, Dim_Products.tmdl 등
│       ├── relationships.tmdl         # 4개 1:N 관계 배선 정의
│       └── model.tmdl
└── K_Retail_Sales_Demo.Report/        # [CLI & Authoring Skill 담당 영역]
    ├── StaticResources/
    │   └── SharedResources/BaseThemes/ # Retail_IQ_Light_KR.json 복사 위치
    └── definition/
        ├── report.json                # 리포트 전역 설정 및 테마 등록
        └── pages/                     # 4개 한글 페이지 및 Visual JSON

필수 1:N 관계 연결 확인 (모델 보기 탭):
• Dim_Products[ProductKey] → Fact_Sales[ProductKey]
• Dim_Stores[StoreKey] → Fact_Sales[StoreKey]
• Dim_Customers[CustomerKey] → Fact_Sales[CustomerKey]
• Dim_Date[Date] → Fact_Sales[주문일자]

Chapter 03 · Deep Dive: MCP & CLIs 현재 위치: 엔진 제어실

MCP 서버와 2종의 공식 CLI는 실습에서 어떻게 작동하는가?

한결전자 실습 데이터를 처리할 때 에이전트가 백그라운드에서 실행하는 3가지 핵심 엔진의 실제 동작입니다.

1. 시맨틱 모델 엔진

Power BI Authoring MCP

실행 중인 K_Retail_Sales_Demo 인메모리 모델과 직접 통신합니다.

  • 인스턴스 탐색 및 연결: 로컬에서 열려 있는 Power BI Desktop 프로세스를 찾아 연결합니다.
  • 한글 스키마 추론: Fact_Sales에 주문수량만 있고 단가가 없음을 발견한 뒤, 스스로 Dim_Products를 읽어 판매단가_KRW와 원가_KRW를 찾아냅니다.
  • 탐색용 DAX 쿼리 실행: 2024년~2026년 상반기까지의 날짜 범위와 원화(KRW) 매출 규모(억/천만 원 단위)를 먼저 조회합니다.
  • 한글 DAX 측정값 생성 및 검증: 총매출액 = SUMX(Fact_Sales, Fact_Sales[주문수량] * RELATED(Dim_Products[판매단가_KRW])) 등 10여 개 측정값을 KPI 측정값 폴더에 생성하고 검증합니다.
2. PBIR 리포트 작성/검증 CLI

powerbi-report-author

패키지명: @microsoft/powerbi-report-authoring-cli

  • 모던 비주얼 규격 조회: 최신 비주얼 타입과 상단 페이지 이동 바인 pageNavigator(v2.1.0)의 정확한 데이터 역할(Role) 바인딩 구조를 조회합니다.
  • PBIR JSON 스키마 검증 (validate): 에이전트가 생성한 4개 한글 페이지(경영진 종합 요약, 제품 및 브랜드 분석, 권역 및 매장 분석, 고객 세그먼트 비교)의 JSON 파일 무결성을 검사합니다.
  • 에러 피드백 루프: JSON 스키마 에러나 테마 선행 오류가 있으면 즉시 라인 위치를 반환하여 에이전트가 스스로 수정하게 만듭니다.
3. 실시간 화면 제어/캡처 CLI

powerbi-desktop (Desktop Bridge)

Power BI Desktop 내부의 로컬 서버와 통신하는 브릿지 CLI입니다.

  • 무중단 실시간 새로고침 (reload): 디스크의 PBIR JSON을 수정한 직후, 열려 있는 Power BI Desktop 화면을 즉시 리로드합니다.
  • 고해상도 스크린샷 캡처 (screenshot): 4개 한글 리포트 페이지가 실제로 어떻게 렌더링되었는지 PNG 이미지로 찍어 에이전트에게 전달합니다.
  • 시각적 자가 교정 지원: 한글 제목이나 네비게이션 버튼(경영진 종합 요약 등)의 레이아웃이 깨지거나 줌 비율이 어긋나면 에이전트가 스크린샷을 눈으로 보고 재수정합니다.

Chapter 04 · Agent Skills 리포지토리: github.com/microsoft/skills-for-fabric

에이전트를 전문가로 바꾸는 4대 Authoring Skills

Microsoft는 microsoft/skills-for-fabric 리포지토리를 통해 에이전트용 플러그인을 제공합니다. 각 스킬(SKILL.md)에는 데이터 시각화 베스트 프랙티스와 엄격한 작업 순서가 정의되어 있으며, VS Code에서 열람 및 우리 회사 표준에 맞게 수정(Edit)할 수 있습니다.

STEP 1 · 기획

powerbi-report-planning

"임원용 대시보드 만들어줘" 같은 모호한 요청을 받아 Guided Q&A를 통해 타겟 독자, 핵심 질문, KPI를 정의하고 승인된 리포트 명세서(report-spec.md)를 확정(Lock)합니다.

STEP 2 · 디자인

powerbi-report-design

코드를 짜기 전 페이지 아키타입(Archetypes), 적절한 차트 유형, 컬러 팔레트, 타이포그래피, 웹 접근성 기준을 먼저 수립합니다.

STEP 3 · 구현 & 검증

powerbi-report-authoring

2종의 CLI를 구동해 PBIR 페이지, 비주얼, 필터, 테마 파일을 생성하고, Desktop 리로드 및 스크린샷 시각 검수 루프를 완수합니다.

STEP 4 · 배포

powerbi-report-management

검증이 끝난 로컬 PBIP 리포트와 시맨틱 모델을 Microsoft Fabric 워크스페이스로 배포하고 관리합니다.

스킬 내부 규칙 해부 (클릭하여 확인해 보세요)

MUST · 에이전트가 반드시 지켜야 하는 강제 사항

  • 시맨틱 모델 선행 검사: 디자인이나 차트 결정을 내리기 전에 반드시 시맨틱 모델의 테이블과 사용 가능한 한글 필드/측정값을 먼저 검사(Inspect)해야 합니다.
  • 두 가지 공식 CLI 사용 강제: 임의로 불완전한 JSON을 추측해서 작성하지 않고, 반드시 powerbi-report-author와 powerbi-desktop CLI가 둘 다 설치되어 있는지 확인하고 이를 통해 작업해야 합니다.
  • Completion Gate (완료 관문) 통과: [파일 편집 → CLI validate 통과 → Desktop reload → 전체 페이지 screenshot 촬영 및 시각적 검토]를 모두 통과하기 전에는 작업 완료를 선언할 수 없습니다.

PREFER · 품질 향상을 위한 권장 사항

  • 핵심 설계 입력만 질문: 결과물에 실질적인 영향을 미치는 누락된 디자인 입력값만 간결하게 질문합니다.
  • 모던 비주얼 및 네비게이터 활용: 다중 페이지 리포트의 경우 사용자가 리포트 안에서 자연스럽게 이동할 수 있도록 최신 pageNavigator(v2.1.0)와 모던 카드/차트 비주얼을 우선 채택합니다.

AVOID · 환각 및 오류 방지를 위한 금지 사항

  • 설계 단계에서 파일 직접 생성 금지: powerbi-report-design 단계에서는 페이지, 비주얼, 필터, 테마나 PBIR 파일을 직접 생성하지 말고 디자인 가이던스만 확정해야 합니다.
  • 레거시/구형 비주얼 사용 금지: 구형 Q&A 비주얼, Bing Maps 등 더 이상 권장되지 않는 레거시 시각적 개체를 생성하지 않습니다.

기업 맞춤형 스킬 수정 (Edit in VS Code)

Claude Code의 Customize > Plugins > PowerBI Authoring 메뉴에서 각 스킬 우측의 Edit > Edit with VS Code를 누르면 로컬에 설치된 SKILL.md 파일이 열립니다. 여기에 우리 회사의 고정 폰트(맑은 고딕/Pretendard), 원화(₩/원) 단위 표기 규칙, 로고 위치 등을 적어두면 사내 모든 분석가가 동일한 표준으로 리포트를 생성할 수 있습니다.

진행 방법: STEP 2에서 연결한 같은 Windows 에이전트 채팅창을 사용하세요. 아래 프롬프트를 한 번에 모두 넣지 말고, 각 단계의 응답과 완료 기준을 확인한 뒤 다음 프롬프트를 입력합니다. 도구가 달라도 세 프롬프트는 공통입니다.


            

              
3-1 · 무엇을 어떻게 계산할지 설계하기

              
왜 하나요? 주문 건수와 주문 항목 수는 다르고, 고객당 매출도 어떤 고객을 분모로 삼는지에 따라 달라집니다. AI에게 곧바로 생성을 맡기기 전에 계산의 의미와 필요한 관계를 확인합니다.

              

                

                  3-1 프롬프트 · 설계만 요청
                  
                

                
STEP 2에서 확인한 모델을 기준으로 KPI 측정값 설계안을 표로 보여줘. 아직 모델은 변경하지 마.
대상: 총매출액, 총원가, 매출총이익, 이익률(%), 총주문건수, 총판매수량, 고객당 평균매출, 전년 동기 대비 매출 성장률 YoY %.
각 항목의 업무 의미, 사용할 실제 열·관계, DAX 초안, 표시 형식, 기존 측정값 재사용 여부를 적어줘.
주문수량과 제품 단가·원가의 관계, 주문번호의 중복, 고객당 매출의 분모, 날짜 테이블·날짜 관계와 전년 데이터 유무를 확인해 줘.
없는 열은 추측하지 말고, 모호한 계산 기준이나 필요한 모델 수정은 나에게 질문한 뒤 멈춰줘.

              

              
완료 기준: 8개 KPI의 의미·계산식·표시 형식을 이해하고, 모호한 기준과 관계 문제를 해결한 설계안이 있어야 합니다. 수정할 점은 이 대화에서 먼저 요청하세요. 동의한 설계안이 준비되면 3-2로 갑니다.

            


            

              
3-2 · 승인한 측정값을 모델에 생성하기

              
왜 하나요? 설계안은 아직 문서일 뿐입니다. 확인한 DAX를 실제 모델에 등록하고 KPI 측정값 표시 폴더에 모아, 다음 보고서 생성 단계에서 재사용할 수 있게 합니다. 표시 폴더는 파일 탐색기의 폴더가 아니라 모델 안의 정리 항목입니다.

              

                

                  3-2 프롬프트 · 설계 확인 후 생성 승인
                  
                

                
앞에서 함께 확인한 최종 KPI 설계안을 승인해. 로컬 Power BI Authoring MCP로 해당 측정값을 모델에 적용해 줘.
같은 의미의 기존 측정값은 재사용하고, 새 측정값은 'KPI 측정값' 표시 폴더에 정리하고 승인한 표시 형식을 설정해 줘.
기존 측정값을 바꿔야 하거나 테이블·관계 수정이 추가로 필요하면, 변경 내용을 보여주고 별도 승인을 받아줘.
적용 후 측정값 이름·DAX·표시 폴더·표시 형식을 다시 읽어 생성·재사용·실패 목록을 보여줘. 실패는 숨기지 마.
아직 보고서 화면을 수정하거나 Fabric에 게시하지 마.

              

              
완료 기준: 승인한 KPI가 실제 모델에 존재하고, 재조회 결과와 생성·재사용 목록이 일치해야 합니다. 생성 오류가 남았다면 해결한 뒤 3-3으로 넘어갑니다.

            


            

              
3-3 · 숫자를 검증하고 저장하기

              
왜 하나요? 수식이 등록됐다고 숫자까지 맞는 것은 아닙니다. 전체 합계와 연도별 결과를 실제로 조회하고, 원본 데이터 기준 계산과 비교해 보고서에 쓸 수 있는 KPI인지 확인합니다.

              

                

                  3-3 프롬프트 · 결과 검증과 저장 안내
                  
                

                
방금 생성·재사용한 KPI를 모델에서 DAX 쿼리로 실행해 전체 합계와 연도별 결과를 표로 보여줘.
매출·원가·수량·고유 주문 수·고객당 매출을 원본 열 기준의 독립 집계와 비교하고, 매출총이익과 이익률도 검산해 줘.
YoY는 비교 가능한 전년 데이터와 날짜 필터를 확인하고, 전년 값이 없거나 0일 때의 빈 값·처리를 설명해 줘.
검사 항목별 통과·실패·확인 불가와 근거를 보여줘. 수정이 필요하면 원인을 설명하고 승인받은 뒤 고치고 다시 검증해 줘.
Desktop에서 PBIP로 저장하는 방법을 안내해 줘. 내가 저장한 다음에는 디스크의 시맨틱 모델 정의에도 측정값이 반영됐는지 확인해 줘.
검증과 저장 확인이 끝날 때까지 보고서 생성이나 Fabric 게시로 넘어가지 마.

              

              
완료 기준: 검증 표에 설명되지 않은 실패가 없어야 합니다. 예상된 YoY 빈 값은 이유를 확인하세요. Desktop에서 저장한 뒤 채팅에 “저장했어. 디스크 반영을 확인해 줘.”라고 입력하고, 반영 확인까지 끝나면 STEP 4로 넘어갑니다.

                STEP 4 프롬프트 · 4페이지 한국어 경영진 리포트 및 페이지 네비게이션 자동 생성
                
              

              
설치된 Power BI 보고서 스킬(powerbi-report-cli, 이전 버전은 powerbi-report-authoring)을 사용해서 K_Retail_Sales_Demo.pbip 파일에 4페이지 분량의 한국어 경영진 리포트를 만들어 줘. 기존 빈 페이지는 삭제해도 돼.
각 페이지 구성은 다음과 같아:
- 1페이지: 경영진 종합 요약 (Executive Summary - 핵심 KPI 카드 5개, 월별 매출 추이, 카테고리별 성과, 연도 슬라이서)
- 2페이지: 제품 및 브랜드 분석 (Product Analysis - 카테고리/브랜드별 매출 및 이익률 비교)
- 3페이지: 권역 및 매장 분석 (Store Analysis - 서울/수도권/영남권/온라인 등 권역별 및 매장 유형별 성과)
- 4페이지: 고객 세그먼트 및 매출 비교 (Customer & Sales Comparison - 고객등급/연령대별 분석 및 전년 대비 비교)

리포트 상단에는 각 페이지로 이동할 수 있는 페이지 네비게이션(Page Navigator) 바를 추가하고, CLI 검증과 스크린샷 캡처 리뷰까지 완료해 줘.

            

          

        


        

          
STEP 05

          

            
한국형 브랜드 테마(Retail_IQ_Light_KR.json) 일괄 적용 및 색상 재정비(Re-sweep)

            
실습 폴더에 함께 들어 있는 맑은 고딕/Pretendard 기반 테마 파일(Retail_IQ_Light_KR.json)을 적용하여 리포트 전체 디자인을 통일합니다.

            

              

                STEP 5 프롬프트 · 한국형 브랜드 테마 JSON 적용
                
              

              
폴더 안에 있는 Retail_IQ_Light_KR.json 파일을 이 리포트의 커스텀 테마로 등록하고, 개별 비주얼에 하드코딩된 색상들을 새 테마 팔레트에 맞게 전체 재정비(Re-sweep)한 뒤 다시 검증해 줘.

            

          

        


        

          
STEP 06

          

            
최종 확인 시 주의사항: "저장하지 않고 닫기 (Don't Save)"

            

              에이전트가 디스크의 PBIR 파일들을 직접 수정했으므로, 만약 수동으로 Power BI Desktop을 껐다 켜서 확인해야 할 때는 기존에 열려 있던 창을 닫을 때 반드시 '저장 안 함(Don't Save)'을 클릭한 뒤 K_Retail_Sales_Demo.pbip를 다시 열어야 합니다. '저장'을 누르면 예전 빈 화면 상태가 에이전트가 작성한 새로운 JSON 파일들을 덮어써 버립니다.
